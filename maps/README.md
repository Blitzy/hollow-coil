# maps

TrenchBroom maps and the editor config. The repo root is the game root, holding `maps/` and `textures/` side by side (the standard Quake layout), so TrenchBroom's game path and qbsp's `-basedir` both point at the repo root.

- `*.map`: maps in Quake 2 (Valve) format. The `.map` file is the source of truth.
- Textures live in the top-level `textures/<folder>/<name>.png` and are referenced by name (`<folder>/<name>`). `textures/dev/` holds placeholder grid and solid-color textures generated by `npm run make-placeholder-textures`.
- `trenchbroom/`: the Mandrel.js game config and FGD. Run `npm run install-trenchbroom` to link it into TrenchBroom, then set the Mandrel.js game path to the repo root in TrenchBroom's preferences.

## Lighting

Light entities use ericw-tools' default linear falloff: a light's `light` value is roughly its reach in units, brightest next to the light and fading to nothing that far away. A 220 light lights about a 220-unit radius. The engine's lightmap brightness is fixed (1.5 on the web: a lightmap value of 170 shows a texture at its true colors), so the same light values look the same in every map. If an area is too dark, add lights or raise their values there; don't change the global brightness. Light also bounces once off surfaces (ericw-tools' default for Quake 2 maps), which softens shadows and spills a little color. Only steady light bounces: a flickering or pulsing light (one with a `style`) lights what it reaches directly, and its bounce never flickers (`npm run compile` passes `-bouncestyled 0`). Keep lights a little away from surfaces: one almost touching a brush makes a hot spot there and harsh falloff around it. The web build draws maps lit, so the fastest preview is `npm run dev` from the repo root and reloading the page after saving.

## Previewing lighting without the game

TrenchBroom doesn't show baked lighting. To see it without an engine, use `lightpreview`, which ships with ericw-tools: run `.tools/ericw-tools/<version>/lightpreview.exe` (installed by `npm run setup`), open a `.map` from this folder, set the **qbsp** field to `-q2bsp`, leave **common** and **vis** empty, set **light** to `-bouncestyled 0` (to match `npm run compile`), and press **Reload**. It compiles next to the map; those outputs are gitignored. Fly with WASD plus Q/E; Alt+1 to Alt+3 switch between lightmapped, lightmap-only, and fullbright views.

## Maps

Units are Quake units. Player and enemy origins sit 24 above the floor (the hull spans -24 to +32), so a marker on the floor at height 0 has origin z = 24. Test scenarios refer to `info_marker` entities by name rather than raw coordinates, so keep marker names stable when editing.

**test_movement**: movement test course, ceiling at 256.

- Four isolated lanes running +x from a shared hall. Each lane's obstacle starts at x = 256, and its marker sits at x = 64. Markers `step16_start`, `step18_start`, and `step20_start` lead to 16-, 18-, and 20-unit steps; `steep_start` leads to a slope rising 128 over 64 (63 degrees, too steep to walk).
- A course from `course_start` (also the player start) to `finish`: stairs of 16-unit steps up to a 64-high platform, a ramp down (64 over 128, 27 degrees), a ramp up (64 over 96, 34 degrees), a 128-wide gap over a pit (with stairs out along the south wall), a 64-unit drop, and a 32-high ledge that needs a jump. The finish pad is green.

**test_combat**: open arena 1536 x 1536, ceiling at 256.

- A full-height center wall blocks sight between `west` (player start) and `east` (shotgunner).
- `north_west` and `north_east` (shotgunner) have clear sight of each other.
- A clear range lane along y = -704: `range_origin`, then `range_128`, `range_256`, `range_512`, and `range_1024` at those distances.
- Four full-height pillars, two low covers (32 high), and an L-shaped wall for general cover.

**greybox_01**: the playable slice. A warm-lit start room, a corridor with two steps up and a flickering light (style 10), and a cool-lit room with two pillars, a raised platform (64 above that room's floor) reached by stairs, and two shotgunners: one on the floor, one on the platform.

New maps must start with `// Game: Mandrel.js` (TrenchBroom writes this when you create a map with the Mandrel.js game).

Compiled `.bsp` files go to `/build`, never here.
