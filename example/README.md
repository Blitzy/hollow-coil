# Mandrel.js Example

The example game: a game directory, like Quake's `id1/`, with the content the engine is played and tested with. It's a sample, not a product. The engine's tests (`/scenarios`, golden demos, and compile tests) use only this content, and every engine behavior is used by something here.

- `data/`: `game.json` (the game's name and start map), plus the player, weapon, and enemy data. See `packages/defs/README.md` for what each file holds; the schemas are there too.
- `maps/`: TrenchBroom maps. See `maps/README.md`.
- `textures/`: textures (PNG), referenced by name from maps. `textures/dev/` holds placeholders generated by `npm run make-placeholder-textures`.
- `trenchbroom/`: the TrenchBroom game config and FGD. `MandrelJSExample.fgd` includes the engine's entities from `mandreljs/mandreljs.fgd`; `mandreljs/` is a link to `packages/defs/trenchbroom/` that `npm run install-trenchbroom` makes (gitignored).

Maps compile to `build/` here (gitignored). The content here is CC BY 4.0, except the TrenchBroom config and FGD; see `LICENSE.md`, which releases carry so the content is always credited, and `LICENSE-EXCEPTION.md` at the repo root.

To make your own game, see [Make your own game](../README.md#make-your-own-game) in the README.
