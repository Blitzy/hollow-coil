# Mandrel.js Example

The example game: a game directory, like Quake's `id1/`, with the content the engine is played and tested with. It's a sample, not a product. The engine's tests (`/spec` scenarios, golden demos, and compile tests) use only this content, and every engine behavior is used by something here.

- `data/`: `game.json` (the game's name and start map), plus the player, weapon, and enemy data. See `packages/defs/README.md` for what each file holds; the schemas are there too.
- `maps/`: TrenchBroom maps. See `maps/README.md`.
- `textures/`: textures (PNG), referenced by name from maps. `textures/dev/` holds placeholders generated by `npm run make-placeholder-textures`.
- `trenchbroom/`: the TrenchBroom game config and FGD. `MandrelJSExample.fgd` includes the engine's entities from `mandrel/mandrel.fgd`; `mandrel/` is a link to `packages/defs/trenchbroom/` that `npm run install-trenchbroom` makes (gitignored).

Maps compile to `build/example/` at the repo root. The content here is CC BY 4.0, except the TrenchBroom config and FGD; see `LICENSE-EXCEPTION.md`.

## Another game

A game made with the engine is a sibling directory with the same layout, checked out from its own repo. Name its FGD after the game (as TrenchBroom's own `Quake2/Quake2.fgd` is), start it with `@include "mandrel/mandrel.fgd"`, and gitignore `trenchbroom/mandrel` in its repo. Then play it at `http://localhost:5173/?game=<dir>`, and pass `-- --game <dir>` to `npm run compile`, `npm run validate`, and `npm run install-trenchbroom`.
